# v1.2.34 订单滑动与余额支付修复

历史检查记录：v1.2.34 本地修复、验证并提供安装包。相关修改统一纳入 v1.2.35 发布，包含客户端导入修复；此发布不自动更新线上站点。订单状态及完整支付流程以 `xboard-payment-import-audit-2026-11-10.md` 的后续检查为准。

## 手机端订单表格

主内容 `.main` 是 Flex 子项，默认 `min-width:auto` 使订单表格的最小内容宽度撑大整个主内容区。页面的 `overflow-x:hidden` 裁掉右侧，而 `.table-wrap` 本身没有溢出，不能左右滑动。

修复主内容区 `min-width:0`，订单表格单独使用 `.orders-table`，最小宽度 720px，单元格不压缩换行。沿用现有 `.table-wrap { overflow-x:auto }`，滚动发生在表格模块内。

`tests/orders-mobile.browser.cjs` 使用生产接口和渲染路径、独立 API 响应数据，在 320/390/430/768/1510px 验证内容区宽度、六列内容、长订单号、最右侧取消操作。手机/平板通过 CDP 触摸事件验证双向滑动。

## 余额支付结果处理

用户说明使用余额支付。当前 Xboard 参考实现 `OrderController::checkout` 在余额已抵扣、剩余金额为零时调用 `OrderService::paid`，返回顶层 `{ "type": -1, "data": true }`。这是同步结算接口响应，不经过第三方支付网关回调。

主题通用 `api()` 原来总是拆出 `data`，将上述响应变成 `true`。`checkout()` 随后访问 `result.type/result.data`，得不到成功标志，支付窗口继续显示“等待支付”。演示接口直接返回完整对象，掩盖了这个真实接口问题。

增加结算调用的 `rawResponse:true`，保留响应类型；其他接口继续按原规则拆出 `data`。成功分支关闭支付窗口、导航到仪表盘，触发重新读取用户余额和订阅。在线支付 URL 分支也能继续读取完整响应；未修改支付网关后台通知逻辑。
